# 变更规格: GitHub 发布整理与配置外显化

## 目标

把当前项目整理到适合公开发布到 GitHub 的状态，去掉不应公开提交的文件与配置，补齐面对外部使用者的 README 和 `.env.example`，并在此基础上增加一个可公开说明的自动巡检能力：每天 8:00 到 18:00 每小时检查一次讲座信息，发现新的符合条件讲座时自动报名。同时，把目前硬编码在代码里的讲座时间筛选规则和巡检参数改造成通过配置文件控制的模块化能力。

## 范围

本次变更包含以下内容：

1. 修改当前运行策略，使程序支持在每天 8:00 到 18:00 之间按小时轮询讲座信息，并在发现新的符合条件讲座时自动报名。
2. 梳理仓库结构，删除明显不适合公开仓库保留的无关文件或一次性调试文件。
3. 完整重写或补强 `README.md`，面向首次使用者说明项目用途、依赖安装、配置方法、运行方式和常见场景。
4. 在 README 中明确说明两种使用场景：
   - 连接校园网，通常不需要验证码时如何运行。
   - 不连接校园网，可能出现图形验证码，且可能额外要求邮箱验证时如何运行。
5. 在 README 中补充项目的后台运行方法，并考虑至少 macOS / Linux 与 Windows 两类系统的常见做法。
6. 重新创建 `.env.example`，用于提供不含私人信息的账号与敏感配置模板，并在 README 中说明如何从模板生成本地 `.env`。
7. 增加公开可复制的配置文件模板，用于承载巡检时间、运行模式与筛选条件等个人配置。
8. 整理 `.gitignore`，屏蔽私人配置、本地缓存、调试产物和不应发布的本地环境文件。
9. 将当前“按时间过滤”的筛选条件从硬编码规则整理为模块化配置能力，作为个人配置保存在本地配置文件中，不把个人筛选偏好写死在公开仓库中。
10. 在 README 中提供当前筛选条件与巡检模式的配置教程，并明确当前版本仅支持按时间窗口过滤。

## 边界

本次变更不包含以下内容：

1. 不改变现有登录、验证码识别、讲座抓取、报名执行和状态持久化的核心业务流程，除非引入按小时巡检配置文件和仓库整理时必须同步调整入口。
2. 不新增新的筛选维度；本轮只把现有时间过滤规则做成可配置模块。
3. 不把真实账号、真实 `.env`、验证码样本、本地缓存或私人调试数据提交进仓库。
4. 不承诺把项目改造成通用平台级产品；目标是“可公开发布、可说明、可按文档运行”。
5. 不在本轮引入新的筛选维度、云端调度服务或系统级守护程序配置生成器；后台运行只提供文档指导，不自动生成各操作系统的服务文件。
6. 不在本轮处理真实站点业务逻辑上的其他新功能，例如新的 OCR 后端。

## 验收标准

满足以下条件时，可认为本次变更完成：

1. 仓库中不再保留明显不适合公开发布的本地文件、私人配置模板缺失问题或调试残留。
2. `.gitignore` 能屏蔽 `.env`、本地缓存、浏览器产物、日志、虚拟环境及其他无关本地文件。
3. `.env.example` 存在且足够完整，用户可以据此创建自己的 `.env`。
4. 公开仓库中存在一个可复制的配置文件模板，用户无需改源码或依赖长命令行参数，就能配置巡检模式与筛选规则。
5. 程序支持在 8:00 到 18:00 按小时巡检，并能在该运行模式下发现新的符合条件讲座后自动报名。
6. `README.md` 明确说明安装、配置、`dry-run`/真实执行方式，以及校园网内外两种登录场景的操作方法。
7. `README.md` 提供后台运行方法，至少覆盖 macOS / Linux 与 Windows 的常见操作方式。
8. 当前时间筛选条件不再只能通过改源码修改，而是能通过个人配置文件完成调整。
9. README 对筛选条件与巡检模式配置给出清晰教程，并明确当前仅支持按时间窗口过滤。
10. 变更完成后，项目的基础命令（至少 `npm run typecheck` 与 `npm test`）仍然可通过。

## 已知前提

1. 当前 README 仍然偏向内部使用口径，对“校园网内无验证码”和“校外/非校园网下可能出现验证码与邮箱验证”的操作说明不完整，也没有后台运行指导。
2. 当前轮询行为主要依赖手动配置 `pollIntervalMs` 与 `maxCycles`，还没有直接表达“8:00-18:00 每小时巡检”的用户级运行模式。
3. 当前公开配置主要暴露在环境变量和命令行参数层，缺少一个面向普通使用者的配置文件入口。
4. 当前时间过滤逻辑直接写在 `src/filter.ts` 与 `src/time-window.ts` 中，不适合公开仓库中的个人化配置管理。
5. 当前工作区仍存在用户自己的 `.env.example` 删除，这正说明模板文件需要在本轮中重建并纳入规范管理。
