# 实施计划: GitHub 发布整理与配置外显化

## 实现方向

这轮变更分成两层：先补一个新的代码能力，再做公开仓库整理。整体方向分成四部分：

1. 巡检调度外显化：把“每天 8:00 到 18:00 每小时检查一次，有新候选就自动报名”做成明确的运行模式，并优先通过配置文件表达，而不是依赖用户自己推导 `pollIntervalMs` 和 `maxCycles`。
2. 仓库发布整理：清理不应保留的文件，补齐 `.gitignore` 和公开仓库应有的模板文件。
3. 使用说明外显化：用 README 把安装、配置、运行、校园网内外两种登录路径、验证码、邮箱验证以及后台运行方式写清楚。
4. 筛选条件配置化：把当前硬编码时间规则抽离为配置模块，使个人偏好保留在配置文件中，而公开仓库只保留模板与说明。`.env` 主要保留账号密码等敏感信息。

实现上优先保持现有登录与报名主工作流稳定，不重写业务链路，而是在配置层和工作流调度层增加更明确的公开接口。配置模型上采用“双层配置”：`.env` 负责敏感信息，配置文件负责可公开的运行参数与筛选规则。

## 执行顺序

1. 先设计配置文件结构，明确哪些配置留在 `.env`，哪些配置迁移到公开可复制的配置文件中。
2. 在新的配置文件模型上实现巡检模式，让程序能直接表达“8:00-18:00 每小时巡检”的运行意图。
3. 盘点当前仓库结构，确定哪些文件应删除、哪些应忽略、哪些应重建。
4. 整理 `.gitignore`，同时恢复新的 `.env.example` 与配置文件模板。
5. 重构配置模型，把时间筛选规则改造成通过配置文件驱动的模块化配置。
6. 调整 README，面向公开用户完整说明配置方法、运行方式、后台运行方式和校园网内外两种使用场景。
7. 做基础验证，确认代码、测试和文档中的命令都与当前仓库结构一致。
8. 更新结果文档和稳定事实文档，记录新的公开发布约束与配置方式。

## 依赖与输入

1. 当前已有的 Node.js、Playwright、TypeScript 自动化代码。
2. 当前已经验证过的真实登录行为，包括校园网外可能出现验证码和新设备邮箱验证。
3. 当前硬编码的时间筛选规则实现，作为新配置模型的业务基线。
4. 用户新增的运行要求：在每天 8:00 到 18:00 之间，每小时自动检查一次讲座信息。
5. 用户新增的配置建议：配置模型优先使用配置文件，而不是命令行参数。

## 关键风险

1. 巡检调度如果直接硬编码在工作流里，容易和现有 `pollIntervalMs` / `maxCycles` 语义冲突，因此需要先明确配置文件模型。
2. 仓库清理时如果误删调试辅助脚本或运行所需模板，可能导致 README 和真实代码不一致。
3. 如果配置文件与 `.env` 的边界没有划清，最终 README 会同时存在两套互相冲突的配置方法。
4. 把时间过滤配置化时，如果设计得过于抽象，容易引入超过本轮范围的“通用规则引擎”复杂度。
5. README 如果没有把“验证码出现时需要 `--headful`”“邮箱验证需要人工完成”以及“后台运行时如何观察失败日志”写清楚，公开用户仍然会误用。
6. `.gitignore` 只能屏蔽未跟踪文件；对已经跟踪过的历史文件，需要通过本轮仓库整理明确地删除或替换。

## 验证方案

1. 对配置层与调度层执行 `npm run typecheck` 和 `npm test`，确认新的配置文件模型、巡检模式与筛选配置接口没有破坏现有逻辑。
2. 人工检查 `.env.example`、配置文件模板与 README 中的变量说明是否一致。
3. 人工检查 README 中的命令是否与 `package.json` 脚本一致。
4. 人工检查 README 中的后台运行方法是否覆盖至少 macOS / Linux 与 Windows。
5. 人工检查筛选条件配置说明是否能覆盖当前唯一支持的时间过滤场景。
6. 人工检查 `.gitignore` 是否覆盖 `.env`、配置文件本地实例、本地缓存、日志、Playwright 产物、虚拟环境和本地实验文件。

## 面向用户的任务拆分

1. 用配置文件定义一个每天 8:00 到 18:00 每小时巡检并自动报名的公开运行模式。
2. 清理仓库结构并补齐对外发布所需的忽略规则、`.env.example` 和配置文件模板。
3. 完成 README，写清楚校园网内外的运行方式、后台运行方式、验证码/邮箱验证处理方式以及两层配置步骤。
4. 将时间筛选规则改造成个人配置文件，而不是源码常量或长命令行参数。
5. 回归验证并记录新的公开发布事实。

## 当前结论

当前范围、执行顺序和风险都已足够明确，可以直接进入执行阶段。后续 `/spec go` 应先确定配置文件模型，再完成巡检调度与筛选配置改造，最后整理仓库结构和 README，因为公开文档必须以最终配置接口为准。
