# 实施计划: UCAS 人文讲座自动报名

## 实现方向

采用 Node.js + TypeScript + Playwright 作为主实现路线。原因是当前已确认登录页使用前端 JavaScript 对密码做 RSA 加密，直接复刻 HTTP 登录流程虽然可行，但对页面细节、隐藏字段和后续跳转更脆弱。浏览器自动化可以直接复用站点现有脚本行为，并更容易处理登录后的人文讲座列表抓取和报名按钮触发。

整体实现分为六层：

1. CLI 与配置层：负责读取 `.env` 与规则配置、处理命令参数、切换 `dry-run`、输出运行摘要。
2. 浏览器会话层：负责启动 Playwright、访问 SEP 门户、检测是否出现验证码、执行登录、确认会话有效。
3. 讲座抓取层：负责进入人文讲座列表页、提取讲座字段、归一化为内部数据结构，并读取页面中的已预约次数与次数要求。
4. 状态记录层：负责持久化记录“已预约”“人数已满”等终态讲座，避免后续运行重复访问和重复报名。
5. 过滤决策层：负责按固定时间规则筛选讲座，并结合终态记录、报名状态和次数上限信息，产出“忽略 / 命中但不可报名 / 命中且可报名 / 达到停止条件”的决策结果。
6. 报名执行层：负责对命中目标触发报名、等待结果反馈、记录成功或失败原因，并在单次运行中去重。

## 执行顺序

1. 初始化项目骨架，建立 Node/TypeScript/Playwright 开发环境，以及基础 CLI 入口。
2. 搭建配置模型，定义凭据、目标页地址、状态文件位置、轮询间隔、验证码识别参数、`dry-run` 等运行参数。
3. 实现登录流程，优先让 Playwright 驱动现有登录页完成表单填充和提交；如果页面出现验证码，则截图验证码区域并调用 OCR 解析，再回填登录表单。
4. 为验证码识别设计失败策略，例如有限次重试、刷新验证码、记录识别结果和最终错误原因，避免无限循环。
5. 实现讲座列表抓取和字段归一化，重点拿到开始时间、报名状态、人数是否已满、已预约次数和次数要求，必要时补充调试快照，确保页面结构变化时便于排障。
6. 实现时间规则判断：仅允许周一 17:00 及以后、周二 19:00 及以后、周三任意时间的讲座进入可报名候选集。
7. 实现本地状态记录，对“已预约”和“人数已满”讲座建立终态缓存，并在后续运行中优先跳过。
8. 实现次数停止条件：当页面显示的已预约次数达到或超过次数要求时，立即停止新的报名动作。
9. 实现报名动作、幂等保护和结构化日志。
10. 补充单元测试、必要的解析夹具、使用说明和运行示例。

## 依赖与输入

1. Node.js 运行时，以及 Playwright 所需浏览器。
2. 有效的 UCAS SEP 账号密码，由用户在本地通过环境变量或 `.env` 提供。
3. 一个本地可写的状态文件，用于保存终态讲座记录和运行元数据。
4. 一种可在本地运行的验证码识别能力，例如 OCR 库或专用图像识别模块。
5. 执行阶段对真实页面的 DOM 结构和报名交互做一次登录后的现场确认，因为当前未登录状态下无法拿到讲座列表的真实标记。

## 关键风险

1. 登录页虽然目前未看到启用中的验证码输入框，但页面存在验证码相关脚本钩子，后端可能按条件启用验证码或限制自动化访问频率、UA 和异常登录行为。
2. 讲座列表页在登录后可能采用服务端渲染、异步表格或弹窗确认，执行阶段需要先探明真实 DOM 和交互链路。
3. 报名动作可能存在二次确认、CSRF token 或状态刷新延迟，不能只依赖按钮点击，需要校验结果反馈。
4. 讲座开始时间的文本格式、时区和星期表达方式可能不统一，解析器需要显式处理并给出失败日志。
5. “已预约次数”“次数要求”“人数已满”这些字段的页面位置和含义需要在登录后确认，避免误把展示文案当成业务状态。
6. 验证码图片的清晰度、干扰线和字符集可能影响 OCR 准确率，需要预留图像预处理和有限次重试策略。
7. 自动报名属于真实账号操作，默认应支持 `dry-run`，避免首次调试时误报。

## 验证方案

1. 对配置解析、时间规则判断、终态记录、验证码识别流程和单次运行去重逻辑编写自动化测试。
2. 对讲座列表解析逻辑保留 HTML 夹具或最小结构样例，重点覆盖时间解析、次数提取和状态提取。
3. 对验证码识别逻辑保留图片夹具或最小样例，验证截图、预处理、OCR 调用和失败重试策略。
4. 对登录和报名链路提供手动 smoke test 指南，因为没有用户凭据时无法在仓库内做全链路自动化验证。
5. 对关键步骤输出结构化日志，至少包含页面进入、验证码检测与识别结果、讲座抓取数量、命中数量、终态跳过数量、已预约次数/次数要求，以及报名动作和失败原因。

## 面向用户的任务拆分

1. 建立自动化脚手架、配置入口和验证码识别依赖。
2. 打通 SEP 登录和讲座页访问，覆盖有无验证码两种登录路径，并提取时间与次数信息。
3. 实现时间过滤、终态讲座记录和 `dry-run` 判定。
4. 实现达到次数要求后的自动停止。
5. 实现真实报名动作与结果校验。
6. 补充测试、文档和运行说明。

## 当前结论

当前范围和验收条件已经足够明确，可以继续保持 `ready` 并进入执行阶段。仍然存在“登录后页面真实结构未知”和“验证码 OCR 准确率不稳定”的风险，但这两项风险都已经被收敛到执行阶段的 DOM 探测、验证码预处理与失败重试实现中，不阻塞开始编码。
