# 验证码与状态持久化事实

## 验证码处理事实

当前项目已经实现了验证码存在时的自动处理路径，相关逻辑位于 `src/captcha.ts` 和 `src/login.ts`。

已实现的稳定行为包括：

1. 检测验证码输入框和验证码图片是否出现。
2. 对验证码图片截图。
3. 调用 `tesseract.js` 在本地执行 OCR 识别。
4. 将识别结果中的非字母数字字符去除后再回填表单。
5. 登录失败且验证码仍存在时，触发验证码刷新并执行有限次重试。

## 验证码边界事实

虽然 OCR 路径已经实现，但当前还没有真实验证码图片样本进入仓库，因此以下内容仍然是已知边界：

1. 尚未验证验证码实际字符长度和字符集。
2. 尚未验证是否存在强干扰线、扭曲或大小写混用。
3. 尚未基于真实样本做图像预处理优化。

因此当前 OCR 更适合被视为“已实现能力，待现场验证精度”，而不是已经完全收敛的稳定高精度模块。

## 状态文件事实

本地状态持久化由 `src/state-store.ts` 管理，默认保存到 `.cache/lecture-state.json`。当前状态文件保存的稳定内容包括：

1. 已预约讲座的标识、标题和时间戳。
2. 人数已满讲座的标识、标题和时间戳。
3. 最近一次读取到的预约次数信息。

## 状态文件使用方式

状态文件在当前实现中承担两个明确职责：

1. 跨运行跳过已经确认终态的讲座，避免重复点击和重复报名。
2. 为后续排障提供最小可追溯信息，例如某个讲座是何时第一次被判定为已预约或人数已满。

当前状态文件不承担历史归档、统计报表或多用户同步功能。
