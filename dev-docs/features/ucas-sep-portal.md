# UCAS SEP 门户与人文讲座站点事实

## 观察日期

以下事实基于 2026-03-17 对公开可访问页面的观察结果，用于指导后续实现和排障。

## 未登录访问人文讲座页的行为

1. 访问 `https://xkcts.ucas.ac.cn:8443/subject/humanityLecture` 时，服务器返回 `302` 到 `/redirect`。
2. `/redirect` 页面会显示“你的会话已失效或身份已改变，请重新登录”。
3. 该页面会在前端脚本中把顶层窗口跳转到 `https://sep.ucas.ac.cn/appStore`。
4. 这说明人文讲座页依赖已经建立好的登录会话，不能直接匿名抓取列表内容。

## SEP 登录入口事实

1. 访问 `https://sep.ucas.ac.cn/appStore` 时，服务端会重定向到 `https://sep.ucas.ac.cn/?loginFrom=/appStore`。
2. 登录页展示标准用户名和密码输入框，没有在默认表单中看到启用中的验证码输入控件。
3. 页面存在一个隐藏提交表单 `#sepform`，实际提交目标为 `/slogin`。
4. 页面脚本 `sepSubmit()` 会读取可见密码输入框的值，使用页面内置 RSA 公钥和 `JSEncrypt` 对密码加密，再写入隐藏字段后提交。
5. 页面脚本中还引用了 `certCode1`、`certCode` 和 `changeimg()`，说明验证码字段和验证码刷新逻辑可能按条件启用。
6. 基于这些事实，浏览器自动化比手工构造 HTTP 请求更稳妥，因为它可以直接复用页面脚本和隐藏字段。

## 对实现的影响

1. 登录能力应优先使用浏览器自动化驱动真实页面，而不是一开始就逆向协议。
2. 真正的讲座列表 DOM 结构必须在已登录状态下观察，当前无法从匿名页面得到列表字段。
3. 如果验证码被启用，登录实现需要具备验证码图片定位、截图、刷新和 OCR 识别能力。
4. 调试链路应保留跳转、截图和 HTML 快照，方便区分“未登录”“验证码失败”“登录失败”和“已登录但页面结构变化”几类问题。
