# UCAS SEP 门户与人文讲座站点事实

## 观察日期

以下事实基于 2026-03-17 对公开可访问页面的观察结果，用于指导后续实现和排障。

## 未登录访问人文讲座页的行为

1. 访问 `https://xkcts.ucas.ac.cn:8443/subject/humanityLecture` 时，服务器返回 `302` 到 `/redirect`。
2. `/redirect` 页面会显示“你的会话已失效或身份已改变，请重新登录”。
3. 该页面会在前端脚本中把顶层窗口跳转到 `https://sep.ucas.ac.cn/appStore`。
4. 这说明人文讲座页依赖已经建立好的登录会话，不能直接匿名抓取列表内容。

## SEP 登录入口事实

1. 访问 `https://sep.ucas.ac.cn/appStore` 时，服务端会重定向到 `https://sep.ucas.ac.cn/?loginFrom=/appStore`。
2. 登录页展示标准用户名和密码输入框，没有在默认表单中看到启用中的验证码输入控件。
3. 页面存在一个隐藏提交表单 `#sepform`，实际提交目标为 `/slogin`。
4. 页面脚本 `sepSubmit()` 会读取可见密码输入框的值，使用页面内置 RSA 公钥和 `JSEncrypt` 对密码加密，再写入隐藏字段后提交。
5. 页面脚本中还引用了 `certCode1`、`certCode` 和 `changeimg()`，说明验证码字段和验证码刷新逻辑可能按条件启用。
6. 基于这些事实，浏览器自动化比手工构造 HTTP 请求更稳妥，因为它可以直接复用页面脚本和隐藏字段。

## 真实登录后的 SSO 事实

以下事实基于带真实账号的 2026-03-17 现场验证：

1. 登录成功后，SEP 会落在 `https://sep.ucas.ac.cn/appStoreStudent`，说明 SEP 门户会话已经建立。
2. 在仅有 SEP 会话的情况下，直接访问 `https://xkcts.ucas.ac.cn:8443/subject/humanityLecture` 仍然可能被带回 `/redirect` 或重新跳回 SEP。
3. 从 SEP 门户中的“人文讲座报名”入口进入后，才能稳定建立 `xkcts` 侧会话。
4. 通过该入口进入后，门户会先落到 `https://xkcts.ucas.ac.cn:8443/subject/humanityNotice`，然后同一会话下再访问 `https://xkcts.ucas.ac.cn:8443/subject/humanityLecture` 可以成功打开讲座预告页。
5. 讲座预告页标题是“讲座预告-选课系统”，页面中真实出现了“报名”“已经预约过”“预约已结束”等状态文案。
6. “报名及听课记录”页真实路径是 `https://xkcts.ucas.ac.cn:8443/subject/humanityStudent`。
7. 该记录页出现了“累计听讲座 8 次，其中有效 6 次”“听讲有效记录15次及以上，即满足听讲要求”这类统计文案，说明真实次数要求至少可以从该页人工确认。
8. 对当前唯一候选讲座执行真实报名点击后，站点弹出了“已超过人数限制，不可以预约。”，说明自动点击已真正触达后端预约校验逻辑。
9. 在验证码环境下，SEP 还可能在登录后把浏览器识别为“新设备”，并跳到 `https://sep.ucas.ac.cn/user/userVisit` 要求做邮箱验证或手机号验证。
10. 用户完成一次新设备验证后，同设备下的后续重跑可以不再出现该验证页面，并继续进入 SEP 门户与讲座页。
11. 2026-03-18 的 README 现场验证表明，普通 `https://sep.ucas.ac.cn/appStoreStudent` 门户页本身不应被视为“新设备验证页”；登录检测逻辑已经调整为优先识别 `userVisit` 这类已知验证页，并跳过普通门户页。

## 对实现的影响

1. 登录能力应优先使用浏览器自动化驱动真实页面，而不是一开始就逆向协议。
2. 要建立 `xkcts` 会话，不能只做 SEP 登录，还必须走一次 SEP 门户中的“人文讲座报名”入口。
3. 真正的讲座列表 DOM 结构必须在已登录状态下观察，当前已经确认预告页和记录页都可以在登录态下打开。
4. 报名结果除了页面静态状态外，还可能以浏览器 `dialog` 的形式返回，因此报名模块必须捕获并分类弹窗文案。
5. 如果验证码被启用，登录实现需要具备验证码图片定位、截图、刷新和 OCR 识别能力。
6. 如果 SEP 触发新设备验证，登录实现需要在 `headful` 模式下保持窗口存活并等待用户手动完成邮箱或手机号验证。
7. 调试链路应保留跳转、截图和 HTML 快照，方便区分“未登录”“验证码失败”“新设备验证”“SEP 已登录但 xkcts 会话未建立”“人数限制弹窗”和“已登录但页面结构变化”几类问题。
