# 仓库基线事实

## 当前仓库形态

当前仓库已经从空目录演进为一个可运行的 Node.js 自动化项目，核心职责是自动登录 UCAS SEP/选课系统并处理人文讲座报名。根目录中已经存在以下稳定实现要素：

1. `package.json` 和 `package-lock.json`：声明 Node 依赖与脚本入口。
2. `src/`：保存自动化实现代码。
3. `tests/`：保存不依赖真实账号的规则测试。
4. `README.md` 与 `.env.example`：说明运行方式和所需配置。
5. `dev-docs/`：继续作为 spec 工作流的权威文档区。

## 已确认的技术事实

1. 当前项目使用 TypeScript 作为主要实现语言，运行方式依赖 `tsx`。
2. 浏览器自动化依赖 `playwright`，默认目标浏览器是 Chromium。
3. 验证码识别依赖本地 Python `ddddocr` 能力。
4. 配置校验依赖 `zod`，测试框架使用 `vitest`。
5. 本地运行状态会保存到 JSON 文件，而不是数据库或远程服务。

## 构建与验证事实

1. `npm run typecheck` 已可通过。
2. `npm test` 已可通过，当前测试覆盖时间规则、次数解析、状态记录和配置解析。
3. `npm start -- --dry-run` 在缺失凭据时会输出明确配置错误，说明 CLI 启动链路已经打通。
4. 真实登录与报名链路尚未在仓库内完成带账号的端到端验证，因为当前执行环境没有用户凭据。

## 仓库级约束

1. `.env` 不进入版本库，账号密码必须通过本地环境注入。
2. `.cache/` 和 `.npm-cache/` 作为运行时缓存目录，不进入版本库。
3. 当前项目默认支持本地单机运行，不包含云端部署或守护进程能力。

## 后续扩展方向

如果后续拿到真实登录后页面样本，最值得继续细化的稳定实现事实有两类：

1. 讲座列表页的真实 DOM 结构、按钮定位方式和状态字段位置。
2. 验证码图片的真实样式、字符集和 OCR 识别成功率。
