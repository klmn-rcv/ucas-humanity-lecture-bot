# 仓库基线事实

## 当前功能状态

当前仓库没有业务代码、工具脚本、测试文件、配置文件或依赖清单，因此还不存在可以称为“功能”的实现单元。现阶段唯一稳定存在的内容是 spec 工作流本身的文档骨架。

## 已确认的实现事实

1. 仓库根目录在初始化时为空。
2. 当前不存在应用入口、命令行入口、服务进程或前端页面。
3. 当前不存在数据模型、接口定义、持久化结构或外部系统依赖。
4. 当前不存在构建链路、测试链路或发布链路。
5. `dev-docs/` 是当前仓库中唯一具备结构化职责的目录，用于支撑后续规范化开发流程。

## 文档结构事实

### `dev-docs/project-meta.yml`

用于声明 spec 初始化已经完成，并作为后续流程是否允许执行的唯一仓库级判定来源。

### `dev-docs/active/`

用于放置当前活动变更的权威文档。在初始化阶段，这里只有现状说明，不代表已经创建某个变更任务。

### `dev-docs/history/`

用于未来归档关键变更快照。由于仓库尚无实现历史，目前为空是正常状态。

### `dev-docs/features/`

用于记录稳定实现事实。当前文件本身就是一个稳定事实说明，目标是防止后续读者误以为仓库遗漏了未登记的已有功能。

## 后续扩展原则

当仓库开始出现真实实现后，`features/` 中的新文档应继续坚持以下原则：

1. 只记录已经存在且可验证的实现事实。
2. 优先说明模块职责、接口边界、主要数据流和约束条件。
3. 不把临时排障记录、失败过程或执行日志写入这里。
4. 如果未来代码规模变大，应按功能域或代码文件拆分成多份文档，而不是持续堆积在单一概览里。
